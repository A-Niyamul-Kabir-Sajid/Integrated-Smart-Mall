# Security and verification

Enforce shop/mall ownership on every server operation. Use framework authentication, password hashing and CSRF protection as appropriate. Keep tokens, API keys and secrets server-side. Validate uploaded files; escape review content; bound queries. Avoid logging raw credentials/proof tokens. Obtain and honor choices for history/camera use; document any external frame processing and retention. Test backup restoration.

Use focused checks: shortest-path fixtures, cross-tenant access denial, concurrent stock/token redemption, idempotent payments/refunds, correct review aggregation, timezone report boundaries, case lifecycle consistency, retrieval evidence, and chronological forecast evaluation. Device-specific AR tests must record device/browser, alignment/drift and recovery behavior. Numeric latency/drift targets are pending baseline measurement and agreement.

Treat emergency information as approved content; do not claim certified emergency evacuation guidance. Offline catalog/map caches need version and stale indicators; do not accept authoritative payment/token/stock transitions offline without a designed reconciliation protocol.

Distinguish planned, implemented and verified status; label simulated integrations and synthetic data. Rendering a dashboard does not establish that its workflows or metrics are correct.
