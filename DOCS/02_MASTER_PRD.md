# Product requirements index

Status: consolidated reading index, **not a newly approved complete PRD**. The earlier project-guide PRD contained placeholders. This index retains detailed requirements at their existing source rather than duplicating them.

Read the [full catalogue](references/functional/DOC/project/FEATURE_CATALOGUE.md), then the feature guides linked from the [13-module map](05_MODULE_MAP.md). The catalogue's 12 sections describe product capabilities, not the current PHP namespace layout.

## Scope and acceptance

- Preserve all catalogue requirements, including optional and deferred items.
- Each feature guide has proposed contracts and completion checks. Treat these as planning input, not implemented endpoints or passing tests.
- Before implementation, record the requested release slice, stable requirement ID, acceptance criteria, data owner, affected consumers, and test evidence.
- Do not expand purchase verification into checkout/payments, create lease or parking tables, or infer new entities from dashboard names.
- Requirement IDs and a complete approved acceptance matrix have not yet been established. Add them as slices are agreed, using [the task checklist](IMPLEMENTATION_CHECKLIST.md).

Consult [CONFLICTS.md](CONFLICTS.md) for unresolved scope and ownership issues. The [original priorities](references/functional/DOC/project/FEATURE_CATALOGUE.md) and [build order](10_BUILD_ORDER.md) guide sequencing without promising delivery dates.
