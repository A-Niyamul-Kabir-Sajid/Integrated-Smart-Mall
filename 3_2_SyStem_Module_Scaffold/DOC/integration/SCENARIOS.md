# Integration scenarios

1. Guest opens a checkpoint, finds a product, selects its shop, obtains a valid multi-floor route and handles AR permission/tracking loss (M02/M03/M12).
2. Customer reserves an item; authorized staff fulfil it; stock and order state agree; receipt exists once (M01/M04/M08/M12).
3. Authorized staff register a purchase; customer redeems its token once; review is correctly verified; report aggregates update (M04/M05/M08/M09/M11).
4. Customer asks for a cold drink; answer uses live product evidence and valid ratings; selected result opens navigation (M02/M05/M06/M03).
5. Visitor reports a broken elevator; mall staff update its case and corridor/connector restriction; new routes avoid it (M07/M10/M03).
6. Shop edits product availability; directory and assistant refresh; no stale availability is presented as current (M08/M02/M06).
7. Monthly reports match hand-calculated source records and correct timezone boundaries; cross-shop exports fail (M09/M11/M12).
8. Payment/parking/POS fixtures remain labelled simulations until actual integrations are tested; duplicate callbacks never repeat side effects (M04/M07/M08/M12).

These are proposed acceptance scenarios. No application checks have run yet.
